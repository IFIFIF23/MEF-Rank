# 实现与来源说明

交付身份：`mef_off_on_handoff_v1`。来源为试验区2的最新统一框架，不恢复旧 A/B/C 或输出侧旁路。原工作区及其冻结文件保持原位，本包为独立交付副本。

## 新增与迁移边界

- 十主干接口来源：`experiments/mef_unified_v1/src/mef_unified/adapters.py`。保留零动作门控、官方核心和同权重第二次前向。
- 主训练损失与训练方式继承当前主预测器入口；新增加密读取、相对路径、训练恢复和历史季度调度。
- Writer、Memory、CAL1 与 K-continuum 数学主体来源于原生 `frozen_source/mef_rank/v371/`；在 `src/mef_delivery/` 中单独适配，不改原冻结源码。
- J306 从导出文件中的原始 FEC 与 mask 重建，shock/FEC scaler 只拟合当前 checkpoint 的训练窗口；不直接消费源文件中的全期参考 scaler。
- B37 使用原生 observable 定义；无 prequential registry 时 P 块保持缺失，不读取测试期标签更新状态。
- 外部主干按股票分块计算，Writer 监督仍覆盖完整合法截面；STR 的跨股票注意力不分块近似。
- Writer 全部 20 repeats、至少 16 个技术有效、含零剂量网格、子集局部标签秩、完整 anchor 覆盖比例 K、联合动作及协方差保留。各子集标签分别进入方向/幅度/外留出函数。
- CAL1 保留至少 20 独立 Episode、Episode-balanced LOEO、J/B 分块距离、Top-5 Episode、至少两邻居和有效样本门、联合不确定性及有界反解；供给不足明确回退。

这是为接通五市场新增并显式登记的抽样差异；原生历史源码和既有候选方案不被回写。FEC 原始缺失门保持不变，不为了让 Crypto 产生动作而填充缺失状态。

## 数据和时间

最终模型：1_str、2018—2022。历史模型：1_memory、五年滚动窗、季度刷新，anchor 为刷新后的日度数据；成熟上限为2022年末。模拟记录可用时间定义为标签成熟日收盘，运行检索严格要求可用日早于查询日；另记录真实 `built_at_utc`。这是离线时钟约定，不声称历史实时部署已经完成。

验证/测试使用原观察数据，2022仅作窗口上下文；2023验证、2024—2026-07-08测试。1_str/1_memory 的 target/source 日期映射加密随附，来源暴露标记永久为非独立样本外。

默认 `both/on` 只训练一份最终权重并保存两组预测。`off` 可单独运行，再用同一目录 `--resume --mode on` 接续历史链。模型、市场、seed、代码、数据与训练配置身份不一致禁止恢复或共享 Memory。

## 验证状态

在委托方要求停止验证之前，迁移前半段运行过十主干原接口的 CPU 合成检查与加密基础测试；这些结果仅覆盖当时的接口版本。此后新增的整链连接、SRSNet最小加载方式、小截面规则和恢复路径**未运行训练验证**，已有检查不能替代最终版本整链验收。没有启动五市场正式训练，没有新增效果结论。

序列化过程的逐分片加密回读属于交付数据完整性处理，不是模型训练实验。来源及迁移差异见 `SOURCE_MANIFEST.json`；接收包文件清单见 `DELIVERY_MANIFEST.json`。

AES-GCM 使用随机96位 nonce、独立256位市场密钥、分片身份作为 AAD。对应 API 及认证失败行为参见 [cryptography 官方文档](https://cryptography.io/en/latest/hazmat/primitives/aead/#cryptography.hazmat.primitives.ciphers.aead.AESGCM)。文件哈希不能替代密码学认证，二者均保留。
